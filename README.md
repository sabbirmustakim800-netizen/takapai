## ম্যাচিংয়ের নিয়ম

সবগুলো একসাথে সত্য হতে হবে:

1. একই **প্রোভাইডার** (বিকাশ/রকেট/নগদ আলাদা)
2. **হুবহু একই টাকার পরিমাণ** (পয়সা পর্যন্ত, ফ্লোট ত্রুটি ছাড়া)
3. **একই প্রেরকের নম্বর** (নরমালাইজড: `+880……` = `01……`)
4. অর্ডারে TrxID দেওয়া থাকলে **TrxID-ও হুবহু** মিলতে হবে
5. এসএমএস এসেছে অর্ডারের মেয়াদের ভেতরে (আগে-পরে সহনশীলতা সেটিংসে ঠিক করা যায়)
6. অর্ডার `pending`, আর এসএমএসটি এখনো কেউ ব্যবহার করেনি

**ভাষা-নিরপেক্ষ পরিমাণ:** অর্ডারে `১০০ টাকা`, `৳100`, `100tk`, `100 TK`, `১,৫০০.০০` —
যেভাবেই লেখা হোক একই পরিমাণ ধরা হয়। এসএমএসেও বাংলা-ইংরেজি মিশ্র ফরম্যাট চলবে
(`১০০ টাকা পেয়েছেন` আর `100tk` দুটোই ১০০.০০)।

**TrxID পুরো সিস্টেমে চিরস্থায়ীভাবে ইউনিক** — একটি বাস্তব পেমেন্ট (TrxID) একবার
ব্যবহার হলে সেটি আর কোনো অর্ডারকে ম্যাচ করতে পারবে না, এমনকি অন্য মার্চেন্টেরও নয়।
এটি ইচ্ছাকৃত: একই পেমেন্টের স্ক্রিনশট/মেসেজ দুই জায়গায় দেখিয়ে টাকা নেওয়ার পথ বন্ধ।

দিকনির্দেশনা (রিভার্স ম্যাচিং): গ্রাহক আগে টাকা দিয়ে পরে অর্ডার দিলেও মিলে যায় —
তখন `match_window_before_seconds` (ডিফল্ট ৩০০ সেকেন্ড) পর্যন্ত পেছনে দেখা হয়।

### এক-বার নিয়ম কীভাবে নিশ্চিত

* ডাটাবেসে ইউনিক ইনডেক্স:
  `UNIQUE (provider, trx_id) WHERE trx_id IS NOT NULL AND status <> 'duplicate'`
  → একই TrxID দ্বিতীয়বার কখনো ঢুকতে পারে না।
* `claim()` একটি `BEGIN IMMEDIATE` ট্রানজ্যাকশনে **দুটি শর্তসহ UPDATE** চালায়:
  `sms_events ... WHERE status='unmatched'` এবং `orders ... WHERE status='pending'`।
  যেকোনো একটি ব্যর্থ হলে পুরোটা rollback — তাই দুইবার টাকা ছাড়ার পথ নেই।
* অ্যাপের রিট্রাইয়ের জন্য `client_event_id` — একই ইভেন্ট পুনরায় পাঠালে
  সার্ভার আগের ফলাফলই ফেরত দেয় (idempotent), নতুন ম্যাচ হয় না।

## ইউনিক ডিভাইস / API কী

প্রতিটি ইনস্টলের জন্য আলাদা, চিরস্থায়ী পরিচয়:

* **পেয়ারিং (সুপারিশকৃত):** ড্যাশবোর্ড → ডিভাইস → *পেয়ারিং কোড তৈরি* (৮ অক্ষর, ১৫ মিনিট, এক-বার ব্যবহার)।
  অ্যাপ কোডটি পাঠালে সার্ভার তার জন্য নতুন `device_id` + `device_key` বানিয়ে দেয়।
* **ম্যানুয়াল:** ড্যাশবোর্ড → ডিভাইস → *কী তৈরি করুন* — কী শুধু একবার দেখা যায়।

নিরাপত্তা: ডাটাবেসে শুধু **SHA-256 হ্যাশ** থাকে; কী কখনো লগ বা রেসপন্সে ফেরত যায় না
(তৈরির সময়টি ছাড়া)। বাতিল করা ডিভাইস সঙ্গে সঙ্গে `403` পায়।

```http
POST /api/ingest
x-device-id: dev_xxxxxxxx
x-device-key: dvk_xxxxxxxx

{"events":[{"client_event_id":"uuid","source":"sms","sender":"16247",
            "text":"You have received Tk 500.00 from 01712345678. TrxID AB12CD34EF",
            "received_at":"2026-11-12T10:30:00.000Z"}]}
```

## webhook যাচাই (অবশ্যই করুন)

প্রতিটি webhook-এ `X-Signature: sha256=<hmac>` হেডার থাকে। **কাঁচা বডি** দিয়ে যাচাই করুন:

```js
const expected = 'sha256=' + crypto
  .createHmac('sha256', process.env.WEBHOOK_SECRET)
  .update(rawBody)               // parse করার আগের স্ট্রিং
  .digest('hex');

if (!crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(req.headers['x-signature']))) {
  return res.sendStatus(401);
}
```

পেলোডে `event: "payment.matched"`, `order` (আপনার `reference`, টাকা, TrxID) ও
`payment` (প্রেরক, ব্যালেন্স, সময়) থাকে। একই অর্ডারের জন্য webhook একবারই যায়
(ম্যাচ একবারই হয়), তবে রিট্রাই হতে পারে — তাই `order.id` দিয়ে idempotent রাখুন।

## নিরাপত্তা ও সীমাবদ্ধতা

**করা হয়েছে:** পাসওয়ার্ড scrypt, সেশন টোকেন হ্যাশড, ডিভাইস কী হ্যাশড + constant-time compare,
রেট লিমিট, CSP ও নিরাপত্তা হেডার, সব কোয়েরিতে `merchant_id` দিয়ে আইসোলেশন,
HMAC webhook, র্যাপার/সার্ভার-সাইডে এক-বার নিশ্চয়তা।

**মনে রাখুন:**

* **HTTPS বাধ্যতামূলক** — প্রোডাকশনে রিভার্স প্রক্সি (nginx/Caddy) দিয়ে TLS দিন, নাহলে ডিভাইস কী প্লেইনটেক্সটে যায়।
* অ্যাপটি **আপনার নিজের ব্যবসার সিমে** চলা ফোনে ইনস্টল করুন — অন্যের ফোনে নয়।
  অন্যের এসএমএস পড়া বাংলাদেশে অপরাধ।
* এসএমএস ফরম্যাট অপারেটর সময় সময় বদলায়। পার্সার একাধিক প্যাটার্ন সামলায়, কিন্তু
  নতুন ফরম্যাট এলে `server/parser.js`-এ প্যাটার্ন যোগ করতে হবে। কাঁচা টেক্সট সবসময়
  সংরক্ষিত থাকে, তাই পুরনো মেসেজ যাচাই করা যায়।
* SQLite একক-ইনস্ট্যান্সের জন্য — বড় স্কেলে Postgres-এ যেতে হবে।
* payment gateway-এর মতো নিয়ন্ত্রিত সেবায় ব্যবহারের আগে আপনার প্রোভাইডারের নীতিমালা দেখে নিন।
* `artifacts/`-এ যে APK আছে সেটি **ডিবাগ কী** দিয়ে সাইন করা — নিজের ফোনে ইনস্টল ও পরীক্ষার জন্য
  পুরোপুরি কাজ করে। Play Store-এর জন্য রিলিজ সাইনিং **আগেই কনফিগার করা আছে**:
  শুধু নিজের কী বানিয়ে `KEYSTORE_FILE` / `KEYSTORE_PASSWORD` / `KEY_ALIAS` / `KEY_PASSWORD`
  দিন, তারপর `./gradlew bundleRelease` — বিস্তারিত `android/README.md`-এ।
